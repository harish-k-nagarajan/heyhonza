# AGENTS.md

Honza is a mobile-first Czech-learning PWA (Next.js 15 App Router + TypeScript). For product intent, architecture, hard rules, and the full command reference, read `CLAUDE.md` first — it is authoritative. This file only adds Cursor Cloud runtime notes.

## Cursor Cloud specific instructions

### Services
There is one service: the Next.js app (dev server on port `3000`). Standard commands live in `README.md` / `CLAUDE.md` / `package.json` (`npm run dev`, `npm run build`, `npm run start`, `npm run lint`). There is no test framework — verification is `npm run lint` + `npm run build` + a manual check on a ~430px mobile viewport (the app renders as a centered "phone stage"; that narrow width is intentional, not a bug).

### The app runs without any secrets, but the core loop needs one
- No secrets are required to boot the UI. The app degrades gracefully.
- **`OPENROUTER_API_KEY` is required for the core tutor loop** (Honza generating replies in `/chat` and `/call`). Without it, the UI, navigation, and onboarding all work, but any attempt to get a reply shows the friendly error `OPENROUTER_API_KEY is missing on the server` on `/` and `/chat`. Add it as a Cursor secret to exercise the conversation end-to-end.
- **Supabase is optional.** With `NEXT_PUBLIC_SUPABASE_URL` + `NEXT_PUBLIC_SUPABASE_ANON_KEY` unset, auth is disabled and the Zustand stores fall back to `localStorage` (this is the intended local pass-through mode). `/welcome`'s "start" button routes to `/signin`; to skip auth in this mode, navigate directly to `/onboarding`.
- **`ELEVENLABS_API_KEY`** is optional and only powers spoken replies on `/call`.
- Quick wiring check without exposing keys: `curl -s localhost:3000/api/health` returns `{ llmConfigured, ttsConfigured, ... }` booleans.

### Gotchas
- **Never run `npm run build` while `next dev` is running** — it overwrites `.next` and strips the running dev server's CSS, which looks like a catastrophic style regression but is only an artifact. Restart dev if this happens. (Repeated from `CLAUDE.md` because it is easy to trip while verifying.)
- `next-pwa` is disabled in dev (expected `> [PWA] PWA support is disabled` log); the service worker is only generated by `npm run build`.
- When verifying DB persistence you must clear `localStorage` first, otherwise the fallback store masks whether Supabase actually persisted anything.
- `scripts/dev-signin.mjs` (inbox-free local sign-in) needs `SUPABASE_SERVICE_ROLE_KEY` and only works when Supabase is configured.
